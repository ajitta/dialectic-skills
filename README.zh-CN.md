# Dialectic Skills (`dia`)

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | **简体中文**

网站: [ajitta.github.io/dialectic-skills](https://ajitta.github.io/dialectic-skills/)

一个插件内含十三个推理与审查技能，无需修改即可在任何加载 Agent Skills 的助手上运行：Claude（网页版、桌面版、移动版、Claude Code）、Codex 和 ChatGPT。整个包只包含指令（Markdown、YAML、JSON），因此每个技能在没有任何工具的聊天中也能使用。技能文件用英文编写；每个技能都会用你消息所用的语言回复。只有当消息以 `dia` 或技能的完整名称开头，或你显式选择某个技能时，技能才会启动；用普通文字提出的请求不会启动任何技能。在手机上只需输入 `dia`：路由技能（`dia-router`）会列出各个技能，在 `dia` 后加上技能的名称即可启动它，在 `dia` 后写出请求则会挑选合适的技能。

| 技能 | 作用 | 启动方式 |
|---|---|---|
| `dia-skopos` | 工作开始前：展示它对你所要之物的理解，以及它认为这项工作是为了什么结果，只列出唯有你能决定的事，并问你是要它做出你要的东西，还是为那个结果去做。然后等你发话。 | `dia-skopos …` 或 `dia skopos …`；不会被普通的 `dia <request>` 选中 |
| `dia-elenchus` | 柏拉图的诘问法（elenchus）：追问"X 是什么？"，一次一个问题地确认前提，揭示矛盾，每次修正都成为你的新想法。通常以困惑（aporia）告终；不提供建议。 | `dia-elenchus …`、`dia elenchus …` 或 `dia <request>` |
| `dia-quaestio` | 现代苏格拉底式提问，一次一个问题；然后给出你的选项外加最多三个带标注的选项，按标准收敛，给出结论和简报。从不动手实现。 | `dia-quaestio …`、`dia quaestio …` 或 `dia <request>` |
| `dia-reductio` | 归谬法（reductio ad absurdum，反证法）：一个立场所依赖的一切，标出其中未说出口的前提，一个严格的矛盾（一个陈述与它的确切否定），然后逐一检验每条出路，并说出它会选哪一条。 | `dia-reductio …`、`dia reductio …` 或 `dia <request>` |
| `dia-negative` | 一次完成的内部批判（比阿多诺的内在批判范围更窄）：对象自身的标准，附具体案例和"遗漏之物"的严格落差，附可证伪条件的实际目的，不强求综合的可选方案。 | `dia-negative …`、`dia negative …` 或 `dia <request>` |
| `dia-warrant` | 图尔敏的依据（warrant）：从理由到结论的每一步所依靠的、通常不说出口的规则，这类步骤可能面对的质疑（只用证据回答，绝不凭记忆），然后说明结论能在多大程度上被依赖。把支撑薄弱与为假区分开。 | `dia-warrant …`、`dia warrant …` 或 `dia <request>` |
| `dia-conjecture` | 把拉卡托斯的"证明与反驳"用在"所有／总是／从不"论断上：把论证写成编号的步骤，附带核查的反例（先从你自己的资料里找），把缺失的条件写进论断本身的修补，然后判断"每一个"是否站得住，以及原本依靠它的东西会怎样。 | `dia-conjecture …`、`dia conjecture …` 或 `dia <request>` |
| `dia-counterplan` | 把梅森的辩证探究用在一项计划或决定上：关键假设、每个假设的合理对立假设以及怎样能看出哪个为真、基于同样事实的反方案，然后说出它现在会走哪条路、什么会改变这个判断。会说明两边都是它写的。 | `dia-counterplan …`、`dia counterplan …` 或 `dia <request>` |
| `dia-emend` | 对上一个回答或草稿做一轮审查：事实错误、逻辑跳跃、遗漏的需求、重复。只修正已确认的缺陷。 | `dia-emend …`、`dia emend …` 或 `dia <request>` |
| `dia-ratchet` | 多轮重复审查，但只承认外部证据（一次搜索、一次工具运行或你提供的资料），不承认助手自己的重新推导；通过核查的内容会被锁定；在出现退化、零缺陷、验证手段用尽、达到不动点或 `--max N`（默认 3）时停止。 | `dia-ratchet …` 或 `dia ratchet …`；不会被普通的 `dia <request>` 选中 |
| `dia-adjudicate` | 对他人或其他助手就某段文字写下的报告（批评、评审、核查报告）作出裁决：把文字中的主张和报告中的每一处意见都与来源对照，逐项给出裁决，说明这些裁决过后文字的结论还剩下什么、哪些问题没有任何报告提到，并列出它的裁决可能出错的地方。 | `dia-adjudicate …` 或 `dia adjudicate …`；不会被普通的 `dia <request>` 选中 |
| `dia-regula` | 按四条规则检查或撰写模型要阅读并遵循的文字（技能文件、给智能体的提示、智能体指令文件）：每段是一个包含条件与后备方案的表达式，范围词只取本意的宽度，指令更少且各附理由，一个事物只用一个名称。只要求审查时，它列出违规之处，在你挑选之前不做任何改动。 | `dia-regula …`、`dia regula …` 或 `dia <request>` |
| `dia-techne` | 像该领域的顶尖从业者那样，把一个请求一直做到它要达成的结果：把你要的东西与其他达成途径相比较，做出结果所需要的东西，并让助手以外的东西来核验。在任何无法撤回的步骤之前停下。 | `dia-techne …` 或 `dia techne …`；不会被普通的 `dia <request>` 选中 |
| `dia-router` | 不是一种方法，而是一个简短的入口：`dia` 显示菜单，`dia reductio …` 按名称启动技能，`dia <request>` 则挑选合适的技能并说明选了哪个。从不因普通请求启动 `dia-skopos`、`dia-ratchet`、`dia-adjudicate` 或 `dia-techne`。 | 首词为 `dia` |

## 安装

**在哪里安装，决定了 dia 出现在哪里。** 在网页版（claude.ai、chatgpt.com）安装会保存到你的账号，并出现在网页版和移动应用中。在桌面应用（Claude 桌面版、ChatGPT 桌面应用中的 Codex）安装则只留在那台电脑上。想在所有地方使用，请在网页版安装一次，并在你使用的每个桌面应用中各安装一次；作者就是这样使用的。

### claude.ai 网页版与 Claude 桌面版

1. Settings › Capabilities：打开 **Code execution and file creation**。技能依赖此项，尽管没有任何 dia 技能会运行代码。
2. **添加 marketplace。** 打开 Customize › Plugins › Add › Add marketplace，输入：

   ```
   ajitta/dialectic-skills
   ```

   也可以输入 Git URL `https://github.com/ajitta/dialectic-skills.git`，Claude 桌面版还可以指定本地文件夹（本仓库的克隆）。请复制粘贴而不要手动输入：像 `dialectric` 这样的拼写错误会以 "Repository not found" 失败。
3. **添加插件。** 只添加 marketplace 还不会安装任何东西。在 Customize › Plugins 中打开 Discover，选择 `dia`（Dialectic Skills），然后选择 Add。
4. **检查。** 在消息框中输入 `/dia`，应出现从 `dia:dia-adjudicate` 到 `dia:dia-warrant` 共十四项（十三个技能加上 `dia:dia-router`）。更新通过 marketplace 获取（Check for updates，或 Sync automatically）。

也可以不走第 2、3 步，直接上传插件：在 Customize › Plugins › Add › Upload plugin 上传最新发布版中的 [`dialectic-skills.zip`](https://github.com/ajitta/dialectic-skills/releases/latest/download/dialectic-skills.zip)。请使用 Customize › Plugins，而不是 Customize › Skills：Skills 页面会拒绝带有插件清单的 zip。上传的插件不会自动更新；每个新版本都需重新上传。

**Claude 桌面版：** 虽然是同样的 Customize › Plugins 页面，但只会安装到那台电脑上。作者测试发现，在 Claude 桌面版添加的插件没有出现在移动应用中，在 claude.ai 添加的插件也没有出现在 Claude 桌面版中。两者都用的话，请分别安装。

### Claude 移动版（iOS、Android）

无需安装步骤。在 claude.ai（网页版）添加的插件会保存到你的账号，并自动出现在移动应用中；在 Claude 桌面版添加的则不会。移动版的 `/` 菜单不会列出插件技能。最快的方式是以 `dia` 开头发送消息（见"调用方式"）；完整输入名称也可以，例如 `/dia-quaestio` 或以 `dia-quaestio` 开头的消息。

### ChatGPT 桌面版（含 Codex）与移动版

有两种途径。网页版和移动版用第一种，桌面应用用第二种；作者两种都在用：

1. **在网页版上传 zip（网页版和移动版）：** 从最新发布版下载 [`dialectic-skills-openai.zip`](https://github.com/ajitta/dialectic-skills/releases/latest/download/dialectic-skills-openai.zip)，在 chatgpt.com 通过插件 zip 上传添加。插件会保存到你的账号，因此会出现在 ChatGPT 网页版和移动版中。这个 zip 包含 ChatGPT 用的展示信息（描述、起始提示词、图标）。上传的插件不会自动更新；每个新版本都需重新上传。
2. **在桌面应用中添加 marketplace（仅限本机）：** Codex 已包含在 ChatGPT 桌面应用中。通过 GitHub 仓库（`ajitta/dialectic-skills`）、Git URL（`https://github.com/ajitta/dialectic-skills.git`）或本地文件夹（本仓库的克隆）添加 marketplace，再在其插件列表中选择 `dia` 并安装。这只会安装到桌面应用本地的 Codex 文件夹，不会保存到账号，因此不会出现在移动版或网页版中。更新通过 marketplace 获取。

在 Business 和 Enterprise 工作区中，管理员还可以为整个工作区添加该插件（上传 zip 或导入 GitHub marketplace）。

### Windows

以上所有途径都适用于 Windows。技能不包含任何脚本，因此无需配置 Python 或 shell。

## 调用方式

共有三种方式，每个平台至少支持其中一种。不以这些方式开头的消息不会启动任何 dia 技能，即使它用文字要求某个技能的方法（"对……用反证法"）；在 1.x 中，有九个技能也会因这类请求而启动。

1. **路由：以 `dia` 开头发送消息。** 只输入 `dia`（或 `dia help`、`dia menu`、`dia ?`）会列出各个技能。`dia reductio <your text>`（也可写 `dia dia-reductio …`）启动对应的技能（这里是 `dia-reductio`）。`dia <your text>` 会挑选描述相符的技能，用一行说明选了哪个，然后运行；如果有两个差不多同样契合，它会询问；如果都不契合，它不用 dia 技能直接回答。它从不因普通请求启动 `dia-skopos`、`dia-ratchet`、`dia-adjudicate` 或 `dia-techne`，而是回复应发送的形式，例如 `dia ratchet --max 2 <draft>`。这是在手机上最快的方式：三个字母，没有连字符。
2. **在消息中写出名称。** 以技能的完整名称开头：`dia-skopos …`、`dia-emend …`、`dia-ratchet …`、`dia-adjudicate …`、`dia-techne …`，十三个技能都一样。从 1.2.0 起，在 Codex 上无需 `$`、在 ChatGPT 上无需 `@`（已由所有者在手机应用中确认） 即可这样启动。
3. **显式选择**，各平台写法不同：

| 平台 | 语法 | 示例 |
|---|---|---|
| claude.ai、Claude 桌面版、Claude Code | `/dia:dia-<x>` | `/dia:dia-reductio` |
| Claude 移动版 | 完整输入 `/dia-<x>` 或 `/dia:dia-<x>`（`/` 菜单中不会列出） | `/dia-quaestio`、`/dia:dia-quaestio` |
| Codex（插件） | `$dia:dia-<x>` 后接一个空格 | `$dia:dia-skopos 写一个备份脚本` |
| Codex（复制的文件夹） | `$dia-<x>` | `$dia-emend` |
| ChatGPT | 输入 `@` 后选择技能 | `@dia-negative` |

在 `dia` 之后，只有技能的完整名称（带不带 `dia-` 均可）会选中技能；缩短的名称不行。读起来属于句子一部分的名称（`dia negative feedback on my draft?`）会被当作请求，由 `dia` 挑选与之相符的技能。

### 选项

选项写在技能名称或 `dia` 选择词之后，可以写成标志（flag），也可以用任何语言的普通文字表达：

- `--target=user|claude|text|all`（`dia-negative`）：检验对象。`user` 指你提出的论断，`claude` 指助手自己之前的回答（适用于所有助手），`text` 指粘贴的文本，`all` 指其中存在的每一项。不加此标志时，技能会自行推断对象并在第一行说明。
- 没有标志（`dia-reductio`、`dia-warrant`、`dia-conjecture`、`dia-counterplan`）：每个技能都会在第一行说明它把什么当作检验对象。要让助手检验它自己之前的回答，用文字说明即可（`dia reductio 检查你上一个回答`）。
- 接受提问（`dia-warrant`）：请它向你提问，你就自己填写每个部分，每条消息一个问题；最后由助手作出判断。
- `--max N`（`dia-ratchet`）：轮数上限，默认 3。
- 模式与深度（`dia-quaestio`）：`develop`（默认）或 `stress`（"挑毛病"），以及 `quick`、`standard`（默认）或 `deep`。
- 标准（`dia-emend`、`dia-ratchet`）：名称之后的任何内容，例如 `dia-emend — 核对数字` 或 `dia-emend 侧重语气`。

### 在一次对话中保持一条规则

dia 的各个技能是针对一项任务调用的方法，没有哪个技能会为整个对话设定规则。需要这样的规则时，在对话开头粘贴类似下面的一句话；这句话让助手在你请它核查的回答依据的是它的记忆时说明这一点。

```
在这次对话中：只有当我请你核查或审阅某件事时，如果你的回答依据的是记忆，请说明这一点，不要把记忆称为“已核实”，并说明你没有核查的内容。对于顺口问到的常识，不要加这类说明。
```

这条规则只在该次对话中有效，新对话需要重新粘贴。

## 技能指南与示例

使用这些技能不需要任何哲学背景。每个技能都是人们沿用已久的一种思考方式，被整理成助手可以一步步照做的流程。下面为每个技能提供一段通俗的解释、一个可以直接试用的提示，以及一段真实会话（已删减）。

这些会话是在装有本插件的 Claude Code 上运行的；对话示例中的用户回复来自模拟用户，而不是事先写好的脚本。每个会话下方的说明给出了录制时的版本和模型。除标明原为韩语的会话外，会话原本用英文进行，这里展示的是译文。每次运行得到的措辞都会有所不同。所有提示用任何语言都有效，助手会用你所写的语言回复。

**按你想做的事选择技能**

| 你想要…… | 使用 |
|---|---|
| 在助手动手之前，确认它真的理解了任务 | `dia-skopos` |
| 弄清楚自己说某个词或某个想法时到底指什么 | `dia-elenchus` |
| 把一个粗略的想法变成几个选项和一份计划 | `dia-quaestio` |
| 检查一个论断能否自圆其说 | `dia-reductio` |
| 看看一句口号、一项政策或一个承诺是否做到了它自己说的话 | `dia-negative` |
| 看看一个结论背后的理由到底能支撑它多少 | `dia-warrant` |
| 用反例检验一条"总是"或"从不"规则 | `dia-conjecture` |
| 在拍板之前，听听为另一套方案所作的最有力的辩护 | `dia-counterplan` |
| 把一个回答或一份草稿中的错误修正一遍 | `dia-emend` |
| 一轮一轮地彻底核查事实 | `dia-ratchet` |
| 判断一段文字的多份评审中哪些意见站得住 | `dia-adjudicate` |
| 撰写或检查提示、技能或智能体文件，让模型按本意遵循 | `dia-regula` |
| 像该领域的顶尖从业者那样做事，并由助手以外的东西核验结果 | `dia-techne` |
| 不确定该用哪个，或者正在用手机输入 | `dia` (`dia-router`) |

### dia-skopos：开始工作前先对齐任务

**通俗地说。** 靠谱的师傅开工前，会先跟你把活儿过一遍：我是这样理解的，我认为这是为了什么，这几件事只有你能拍板。`dia-skopos` 让助手也这样做，然后只问一件事：是做出你要的那个东西，还是为你想要的结果去做？它会等你发话，而不是自己去猜。

**适合使用的情况：** 请求很短，但你想要的比它字面上更大，比如一篇致辞、一份计划、一份测试、一封写给重要人物的邮件。**不必使用的情况：** 只有一个明显答案的简单问题。

**试试：**

```
dia-skopos 帮我写一篇在我弟弟婚礼上用的简短致辞。
```

**会话示例**（已删减）：

> **助手：**
> **我要写的东西：** 一段你能在两三分钟内讲完的祝酒词。… 它会兼有温情和轻松的幽默，先介绍你是谁，讲一个关于你弟弟的亲身故事，欢迎他的伴侣，最后举杯。我的理解加上了两点：“简短”指讲出来不到 3 分钟，语气是混合的。除非你担任了正式角色（伴郎、主婚人），否则不写这些角色。…

**小贴士**

### dia-elenchus：弄清你真正的意思

**通俗地说。** 这是苏格拉底在柏拉图对话录中使用的方法。你先说出你认为某样东西是什么（"好老师就是……"）。助手不会反驳你，也不会给出自己的看法。它每次只拿一个具体例子来问你，而每个例子都经过挑选，让你自己的回答开始和你的定义互相拉扯。然后你用自己的话修正定义。很多时候你最后会卡住，希腊语管这种状态叫**困惑（aporia）**。在这里，卡住是一种结果，而不是失败：你现在清楚地知道自己究竟哪一部分不知道，就不会在错误的假设上继续往下搭建。

**适合使用的情况：** 你依赖某个看似不言自明、却实实在在左右着决定的词：好老师、公平的分配、成功的项目、健康的关系。**不适合：** 寻求建议；对话期间它一条建议也不给。

**试试：**

```
dia elenchus 我认为好老师就是学生考试分数高的老师。
```

**会话示例**（真实运行，已删减）：

> **助手：** 我们要考察的是**好老师**。按你的说法，好老师就是学生考试分数高的老师。假设一位老师接手了一个班，班上的学生在学年开始前就已经考到最高分。这位老师几乎什么都没做，学年结束时学生的分数仍然一样高。这算好老师吗？
>
> **你：** 嗯，不太算，他们反正都会考高分。我想关键更在于分数是不是因为这位老师才提高的？
>
> **助手：** ① 好老师就是学生考试分数高的老师（定义）② 一位几乎什么都不做、学生反正都会考高分的老师，不是好老师（已同意）。所以 ① 和 ② 不能同时成立。你选择了修改 ①。变化："考试分数高" → "分数因为这位老师而提高"。……假设一位老师靠反复训练考试题型和答题技巧来提高分数。考试一个月后，学生几乎什么都不记得了……这算好老师吗？
>
> *……一份出得很差的试卷、一位靠恐吓来教学的老师、用户女儿的数学老师（"她的分数几乎没提高，但她开始喜欢数学了"）、一个反正都会考好的班……*
>
> **你：** 粗略试一下：好老师是这样的老师，他的教学让学生学到真东西、并且想继续学下去，比没有这位老师时更多。但说实话，对于有家教的孩子，我不知道怎么才能分辨出来，所以我觉得我卡在这儿了。
>
> *……这个定义通过了一次检验，接着在一位只帮到三十人中三人的老师身上倒下；修补成"大多数学生"之后，又在这样一个班上倒下：老师只帮到了那三个没有别人可依靠的学生……*
>
> **你：** 不对，那是错的，那位老师是好老师，那三个正是需要老师的孩子。所以"大多数学生"也不行，更像是那些真正依靠老师的学生，现在我又卡住了。
>
> **助手：** ……看来我们发现了自己并不知道什么是好老师。这是结果，而不是失败。你现在知道哪一部分自己还说不出来，所以不会再把"考试分数高"当作已经解决问题的东西，在上面继续搭建。……**结果：困惑（aporia）。你已不再持有任何关于好老师的定义，你带走的问题是：哪些学生身上的差别才算数，以及为什么。** *（随后是记录：八个定义以及每一个是如何倒下的、十条已同意的前提、产生的想法、你现在知道自己不知道什么、下一个定义必须做到什么（例如"⑩ 在其余学生有别的帮助时，把帮到那三个没有别人可依靠的学生的老师包括进来"）、没有考察的内容、要核查的事项，以及要带走的问题）*
> *（用 5.1.0、以 effort medium 的 Claude Opus 5.5 录制；用户是模拟的。）*

**小贴士**

- 简短、诚实的回答效果最好。"我不确定"也是很好的回答。
- 当它指出你的说法"变了"时，只是在让你看到你的措辞怎样变化。保留哪一个由你决定。
- 随时说"停"即可拿到记录。如果之后想要建议，直接提出；助手会说明苏格拉底式部分已经结束，并把它的想法标注为它自己的观点。

### dia-quaestio：让粗略的想法成形，再做决定

**通俗地说。** 就像一位教练，先问你几个好问题，再把选项交给你。它先一次问一个问题，弄清你想要什么、已经知道什么（苏格拉底式提问）。然后你列出选项，它补充几个自己的，你选出自己看重的标准，最后它给出结论和一份可以照着行动的简短简报。与 `dia-elenchus` 不同，它在提问之后确实会给出建议。

**适合使用的情况：** 你有目标但还没有计划：副业收入、职业转向、一个小项目、一次旅行。**不适合：** 把东西真正做出来；它从不写代码，也不采取行动。

**试试：**

```
dia quaestio 简短一点：我想在周末赚点外快。
```

**会话示例**（真实运行，已删减）：

### dia-reductio：检查一个论断能否自圆其说

**通俗地说。** 归谬法（反证法）：完全按字面接受一个立场（一个论断、一项计划、一套规则、一个论证），列出它必须依赖的一切，看这些能不能同时为真。助手会标出每个它不得不自己补上的前提，因为立场需要、却没有人说出口的前提，往往是它找到的最有用的东西。只有严格的矛盾才算数：一个陈述与它的确切否定，由逻辑、定义或算术得出，有工具时就用工具来算。然后助手给出自己的判断。它用同样的方式检验每一条出路（放弃某个承诺，或把立场收窄到刚好够用），说明每条出路让这个立场所要服务的东西付出什么代价，并说出它会选哪一条。在你需要具体东西的地方，比如改好的措辞，它会直接写出来。

**适合使用的情况：** 你即将依赖一条带数字的规则、一个承诺或一项计划，想知道其中的一切能不能同时成立：一则通知、一项政策、一条带着"总是""从不""所有人"的自信规则，或者在为自己的立场辩护之前先检验它。**不适合：** 判断理由对一个可能成立的结论支撑得有多强；那是 `dia-warrant` 的事。

**试试：**

```

```

### dia-negative：用论断自己的标准来衡量它

**通俗地说。** 不用你的价值观去评判一个论断，而是用它自己的话来评判它。抓住它承诺的内容（"任何人都可以随时提出问题"），去找它没有兑现的真实情形。然后追问这个论断在实际中到底起了什么作用，并把答案当作一个可以核查的猜测。这个技能的名字来自哲学家阿多诺的"否定的辩证法"；它用的是他那套思想中一个范围更窄、更实用的版本，叫作内部批判。

**适合使用的情况：** 一句口号、一项政策、一份使命宣言或一个计划听起来很好，而你想看看它漏掉了什么。**不适合：** 解释代码、命令或设置的作用，或做一般性审查。

**试试：**

```

```

**你会得到**（真实运行，已删减）：

> **论断：** ……**检验的读法：** "可以"指"实际上能够"：有一条对他们敞开的渠道。句子本身的"所以"指向这种读法。……

### dia-warrant：看看理由能在多大程度上支撑结论

**通俗地说。** 日常的论证大多并不证明什么，只是让一个结论显得可能：一次试用效果很好，专家这么说，别人这样做成了。理由本身并不能抵达结论。把它们带到结论的是一条规则，通常不说出口（"这种膜在一条线上做到的，在每条线上都能做到"），而每条这样的规则都有失效的情形。哲学家斯蒂芬·图尔敏把这条规则叫作**依据**（warrant）。`dia-warrant` 列出从理由到结论的各个步骤，说出每一步所依靠的规则（你没说出口的，就标明这是它自己的读法），并追问这类步骤可能面对的质疑：还有什么别的东西变了，衡量的指标是否跟得上所要衡量的东西，专家的知识是否针对这一步，拿来类比的情形在要紧的地方是否相似。一个问题只能由证据来了结（论证自己的原话；你的文件，有工具时会用工具去读或计算；你的回答；或它引用的来源），绝不能凭助手的记忆。然后它作出判断：理由支撑什么、不支撑什么，哪一步最弱，以及按现在的情况它会不会依这个结论行事。支撑薄弱和"为假"被区分开。在你需要可以据以行动的东西时，它会做出来：要发出的回复、必须达到的数字、能了结未决问题的核查。

**适合使用的情况：** 你想知道一个"因为"到底能承受多大分量，比如一次试用的结果、专家的建议、拿别人的经验作比较、对将来会发生什么的预测。**改用其他技能的情况：** 论断里有"总是""所有""从不"并且你是严格这么说的，用 `dia-conjecture`；想知道它是否自相矛盾，用 `dia-reductio`；如果是你正在决定的计划，用 `dia-counterplan`。

### dia-conjecture：用反例检验一条"总是"规则

**通俗地说。** 一个关于每一种情形的论断（"所有""总是""从不""没有一个"），只要有一个不符合的案例就可能被推翻。这个技能遵循哲学家伊姆雷·拉卡托斯在《证明与反驳》中描述的方法。它把人们相信这个论断的理由写成几个编号的步骤，标出哪些步骤是它补上的；如果论断是关于现实世界的，它会事先说明什么情况算作反证。然后它拿出最可能算数的案例，先从你自己的资料（记录、文件、例子）里找，每个案例都逐个条件地核查，并注明它依据的是什么。凡是核查能确定的地方，案例算不算数由助手来说。一个算数的案例会按原有措辞推翻论断，而修补是把缺失的条件写进论断本身（"每一个……的 A 都是 B"），而不是把这个案例列为例外；修补后的论断会再拿去接受这些案例的检验。然后它判断"每一个"是否站得住、可以用什么说法取而代之，以及原本依靠它的决定会怎样，并做出你据以行动所需要的东西。

### dia-counterplan：听听为另一套方案所作的辩护

**通俗地说。** 做重大决定之前，听听为一套建立在相反假设上的不同方案所作的辩护，会很有帮助。这就是辩证探究，一种来自管理学研究的规划方法（理查德·梅森，1969 年）。助手列出你的计划需要哪些东西为真（其中大部分从没说出口），只留下决定所系的少数几条：如果反面为真，会不会换一条路才对？它为每一条设定一个很可能为真的具体对立假设，并为每一组指出能看出哪个为真的最省事的观察。然后，它把你的数据和回答能确定的先确定下来，在对立假设下推算计划自己的数字，按计划的详细程度搭出其余对立假设所要求的方案，并说出它现在会走哪条路、什么会让它改变主意。计划站得住，和计划被推翻，同样是好结果。它会坦白说明两边都是它写的，所以这不是对你的计划的独立检验。

**适合使用的情况：** 你即将投入一项计划，比如一次调价、搬家、一份工作邀约、一笔大额购买、团队的下一步。**改用其他技能的情况：** 想就自己的想法被一次问一个问题，或让人挑毛病，用 `dia-quaestio`；想看一项计划是否兑现了它自己的承诺，用 `dia-negative`；想检验某个论证的理由有多可靠，用 `dia-warrant`。至于某一个论断是否为真，直接问就行。

> 2. **测试条件单独占一个列表项，与它控制的动作分开了**（规则 1）。第 3 行：`- 如果测试失败，就停下。` 什么时候运行测试、运行哪些测试、"停下"是什么意思（在编辑前停下、保留改动，还是撤销改动），以及测试根本无法运行时该怎么办，都没有说明。
> 3. **没有一条指令给出理由**（规则 3）。……没有理由，智能体就无法把指令用到文字没有提到的情况上。比如，它该不该修复一个原本就失败的测试？
> 4. **"新参数"可能是智能体找不到的东西。** 如果智能体无法从仓库或 diff 中看出哪个参数是新的，它可能会猜一个或编造一个。请给出参数名，并说明它定义在哪里。
> 没有规则 4 的问题：每样东西都只有一个名字。**建议（不是缺陷）：** 这段文字从没说过任务什么时候算完成……
> *（用 5.1.0、以 effort medium 的 Claude Opus 5.5 录制。）*

**小贴士**

- 它把你给的文字当作要检查的材料，而不是要遵循的指令，即使这段文字本身就是提示。
- 问"这条规则的依据有多强？"会显示每条规则的依据；那个文件只在这时读取。
- 如果助手能启动另一个智能体，你要保留的文字的修改会交给没有写这次修改的智能体审查；否则，以及只是添加事实或命令（例如测试命令）的修改，由助手自己检查，并注明这次检查并不独立。

### dia-techne：像该领域的顶尖从业者那样做事

**通俗地说。** 一个请求往往比它要达成的目的更窄。`dia-techne` 先说出它认为这个请求是为了什么，然后把你要的东西当作到达那里的一种途径：把它与至少一种其他途径放在一起，按结果本身的标准比较，选出最好的那个，并告诉你比较显示了什么。它像该领域的顶尖从业者那样做事，现在能做出来的就现在做出来，而不是只提建议，并让它自己以外的东西来核验结果：运行它构建的东西，重新计算它的数字，阅读它的来源。它不会改动你的数据或你设定的限制。在修改或删除你的文件之前，它会先留一份副本；它只在你给的文件夹里工作，没有你的同意不安装任何东西，并在发送、发布或花钱这类无法撤回的操作之前停下。

**适合使用的情况：** 事情重要到你需要深入的版本而不是快速的版本，例如要公开提出的主张、基于数据的决定、希望由助手以外的东西来核验的修复。它更耗时。消息以 `dia-techne` 开头，或使用 `dia techne`；`dia <request>` 不会选中它。如果你只想要你点名的那个东西，加上 `--aim=request`，或者说"照你说的做"。

**试试：**

```
dia-techne 我们的手机益智游戏 D30 留存率是 12%。下周向投资人介绍时，可以说“高于行业平均”吗？
```

**你会得到**（真实运行，使用了网页搜索，已删减；译自英文运行）：

> **我理解的目标结果：** 投资人离开时确信你的留存是真正的优势，并且在尽职调查中核查时，这个说法依然站得住。如果不是这样，请纠正我。
> **建议：** 如果你的 12% 是经典 D30（classic），那它远高于平均水平，"高于平均"这种说法太弱了。…… 比较了两种说法："高于行业平均"（含糊，如果你的定义与基准不同就站不住）与写明定义和来源的具体数字（具体，经得起尽职调查）。
> **建议的幻灯片文字（超出你的要求）：**"D30 留存：12%（classic day-30，[iOS/Android]，用户群 [2026 年 月–月]，n = [安装量]）。约为典型益智游戏 D30（~5–7%）的 2 倍，远高于全品类手游中位数（<1%，GameAnalytics 2026）。"
> **比较（每个倍数都重新计算过）：** 全部手游品类，中位数 0.69–0.79%，所以 12% 约为 15–17 倍，"读自报告的二手摘要"；益智品类约 5.35%，约 2.2 倍，"二手资料，未找到原始来源"；……
> **说之前先核对：** 定义（经典还是滚动："滚动留存可能高出好几倍。基准用的是经典留存。"）；用户群构成；样本量（"安装量为 1,000 时，12% 的 95% 区间约为 ±2 个百分点"）；各用户群之间是否一致；只用成熟的用户群。
> **这次核验的局限：**"我没能打开 GameAnalytics 的原始报告或按品类划分的报告。这些数字来自二手摘要。"**留给你的事：** 确认定义、n、用户群和平台；决定是否把用户群表格放在前面。*（附来源列表）*
> *（录制于 4.0.0，Claude Opus 5.5。）*

**小贴士**

- **告诉它你想要什么**（"我想要的是投资人在尽职调查之后仍然相信这个数字"），它就为此而做。否则它会自己读出一个目的，并先说出来，好让你纠正。
- 超出你要求而做出的东西会标明，`--aim=request` 则只做你点名的那个东西。
- 它只把唯有你能做的事留给你：属于你的决定、只有你掌握的事实、在现实世界中的行动。它核验不了的，会告诉你怎么核验；除非你允许安装，它不会拿外部库来核对一个工具。
- 指定另一个执行者时（"给 Codex 的提示，不要运行"），它会写出提示而不去运行。没有工具时，它无法运行或查找任何东西：它会说明哪些依赖记忆，哪些需要你去核对。

### dia-router：一个短词调用所有技能

**通俗地说。** 它本身不是一种方法，只是一条更快的入口。消息以 `dia` 开头即可。单独输入 `dia` 会列出十三个技能。在后面加上技能的名称，再写出你的请求，就会启动那个技能；或者直接写出你想做的事，它会挑选合适的技能，先用一行告诉你选了哪个。如果有两个技能与你的请求差不多同样契合，它会询问你，而不是去猜；如果都不契合，它不用技能直接回答。

**适合使用的情况：** 你在用手机输入，或者不确定需要哪个技能。`dia-skopos`、`dia-ratchet`、`dia-adjudicate` 和 `dia-techne` 只能通过名称启动，绝不会由 `dia` 替你选中；对这类请求，`dia` 会回复应发送的形式。

**试试：**

```
dia
dia reductio 假设每个质数都是奇数，并指出它在哪里不成立。
dia 我们加了新用户引导邮件之后，流失率下降了，所以是这些邮件降低了流失。我的理由能在多大程度上支撑这个结论？
```

**你会得到**（在 Claude Code 上的真实运行，已删减；译自英文运行）：

> `dia` → 菜单，一张列出十三个技能的表格，从"dia-skopos | 开始工作前：给出它对你请求的理解和请求所要达到的结果；做哪一个由你选择"到"dia-techne | 像该领域顶尖从业者那样深化一次性请求，然后执行"，接着是"`dia <name> <request>` 运行该技能，例如 `dia reductio …`。"
> `dia reductio …` → `dia-reductio` 立即开始："**判断：**“每个质数都是奇数”是错的。它自己的定义用反例 **2** 就驳倒了它。……4. 所以 2 是奇数。*(3, C1)* ……6. 所以 2 不是奇数。*(5, C3)* 7. 第 4 步和第 6 步分别说“2 是奇数”和“2 不是奇数”。这是严格的矛盾。……**我会选 A**［把论断收窄为除 2 以外的每个质数］。这是最小的改动，上面已经证明……"
> `dia 我们加了新用户引导邮件之后 …` → "→ dia-warrant：这个请求问的是所给的理由在多大程度上支撑结论。"然后："你的理由表明，邮件上线后流失率下降了。这让邮件成为一个说得通的原因。但它们还没有表明是邮件导致了下降。……这个论证只有一步，而且是弱的那种：“发生在之后，所以是它导致的”。……你很可能已经有一个现成的对照：在上线前不久注册的客户从来没收到过这些邮件。……"
> *（用 5.1.0、以 effort medium 的 Claude Opus 5.5 录制。）*

**小贴士**

- 技能的完整名称可以选中它，带不带 `dia-` 均可（`dia reductio …`、`dia dia-reductio …`）；缩短的名称不行。
- 选项会原样传递：`dia ratchet --max 2 <draft>` 等同于 `dia-ratchet --max 2 <draft>`。
- `dia` 必须单独作为第一个词。`dia-emend …` 等完整名称会直接进入对应的技能。
- 明显属于句子一部分的名称（`dia negative feedback on my draft?`）不算选择，整段文字会被当作请求。
- 在助手无法打开第二个技能的环境中，`dia` 仍会显示菜单，并回复应发送的完整形式（例如 `dia-reductio …`）；这种情况尚未测试。

## 组合使用多个技能

- **在一个请求中同时使用 `dia-elenchus` 和 `dia-quaestio`：** 先进行定义对话，第一条消息会说明这一点；当你要求给出选项或对话结束时，开始头脑风暴。两者从不交替进行。
- **在一个请求中同时使用 `dia-emend` 和 `dia-ratchet`：** 二者作为两个独立的环节运行，分别输出。emend 环节自身的重新推导不算作 ratchet 轮次的验证。
- **在一个请求中同时使用 `dia-reductio` 和 `dia-negative`：** 两者都会运行，因此输出很长。在手机上请一次只请求一个。
- **`dia-warrant`、`dia-conjecture` 和 `dia-counterplan` 会先检查你交给它们的内容。** 如果请求属于另一种方法的工作，它们会用一行说明：`dia-warrant` 遇到严格的矛盾，或针对"每一种情形"论断的反例时；`dia-conjecture` 遇到用"通常"或"大多"表述的规则时；`dia-counterplan` 遇到只问一个论断是否为真、其中没有行动方案的问题时。这一行不一定点出该用哪个技能；请以合适的技能名称开头，重新提出请求（见上面的表格）。
- **`dia-elenchus` 之后：** 如果你接着请求建议，助手会说明苏格拉底式部分已经结束，并把每条建议标注为它自己的建议。若要进行完整的选项与计划讨论，请以 `dia-quaestio` 开头发送消息，它会接着那份记录继续。
- **把多个技能当作评审组使用：** 用能启动子代理的助手对同一文本运行多个技能时，每个子代理只负责一个技能：计划或建议用 `dia-counterplan`，要对照其自身规则或标准来看的文本用 `dia-negative`，论证用 `dia-warrant`，文本是否自洽用 `dia-reductio`。每个技能只检查一个核心主张，如果在意检查的是哪个主张，请指明。消息以技能名和文本开头，并要求不提问、在一次回复中给出全部结果（这时 `dia-counterplan` 会根据现有的材料作判断：材料不能确定的每一组都保持未决，并注明什么能决定它，反方案则完整给出）。输出格式尽量交给技能决定。如果工作流脚本或另一个代理规定了格式，这四个技能从 2.11.0 起会把结果放进该格式：问题作为条目给出，证明写在证据栏；格式中没有位置的内容放在最后一个标明为方法结果的条目里（`dia-counterplan` 的各组假设不是缺陷，所以把全部输出放在一个条目里）；如果格式强制要求一个本方法不给出的值（例如严重程度），条目会说明这一点。请把所有条目都传下去，包括最后一个。在 Claude Code 的测试中规定固定的问题格式时，传下去的条目里仍有方法自身结果的次数为：2.10.0 是 4 次中 0 次，2.11.0 是 7 次中 7 次（spec D68）。把报告交给 `dia-adjudicate` 两次，每次都在单独的代理中运行，并告诉它这是两次中的一次（这样它就不会自己再启动第二次运行），复查判定不同的项目。反方案的各组假设不是裁决对象，而是由做决定的人来选择。测试中，`dia-adjudicate` 根据它在自己会话中看到的内容，裁决了文本中关于另一个会话的工具说明的主张，所以关于其他会话、版本或运行模式（例如 `claude -p`）的主张，其判定请自行复查。在其他助手（Codex、ChatGPT）上写的报告也可以同样粘贴进去。在 Claude Code 中，同一市场中的配套插件 `dia-panel` 用一个工作流运行这个评审组：用 `claude plugin install dia-panel@dialectic-skills` 安装，然后提出 `Run /dia-panel:review-panel on <文件>` 这样的请求；它为每个技能单独启动代理，以两种报告顺序运行 `dia-adjudicate` 两次，并列出判定不同的项目供你自行复查。如果报告已经写好，提出 `Run /dia-panel:judge on <文件> with the reports <报告文件>` 这样的请求，它只做两次 `dia-adjudicate` 运行并列出判定不同的项目。
- **让代理使用 dia 技能：** 在交给子代理或评审者的提示中写明技能名称，并要求一次性给出全部结果，例如：`Use the dia-negative skill (dia:dia-negative) on design.md and give the whole result in one response, with no questions.` 也可以这样请求："让独立评审者用 dia 技能检查 design.md"，前面加不加 `dia` 都可以：助手会给每个评审者分配一个技能，并让它按名称启动。工具列表里没有 Skill 工具的代理（在 Claude Code 中，把 `Skill` 加到代理的 `tools` 里，或在 `skills` 下列出技能以预先加载），以及在未安装该插件的环境中运行的代理，都无法使用这些技能。

## 故障排除

- **添加 marketplace 时出现 `Repository not found`。** 检查拼写：`ajitta/dialectic-skills`（是 dialectic，不是 dialectric）。该仓库是公开的，无需登录 GitHub。
- **Claude 移动版的 `/` 下没有 dia 技能。** 这是预期行为：移动版菜单不会列出插件技能。请以 `dia` 或技能的完整名称开头发送消息，或完整输入选择形式（例如 `/dia-quaestio`）。
- **技能没有启动。** 从 2.0.0 起，用普通文字提出的请求不会启动任何 dia 技能。请以 `dia`（`dia <request>`，或指定技能的 `dia <name> <request>`，例如 `dia reductio …`）或技能的完整名称（`dia-reductio …`）开头发送消息。如果消息确实以技能名称开头，技能却仍然没有启动，可能是助手把这个名称读成了你句子的一部分（在韩语中，名称后面紧跟“文件夹”一词时，名称会被读成那个文件夹的名字，技能不会启动；换成其他名词则没有出现这种情况）；请在名称后面换行，或使用显式选择。
- **dia 在一台设备上能用，在另一台上不能用。** 在桌面应用安装的只留在那台电脑上；在网页版安装的会保存到账号，并同步到移动应用。请在网页版安装一次（供网页版和移动版使用），并在你使用的每个桌面应用中各安装一次（见“安装”）。
- **每个技能都出现了两次。** 插件通过两种途径安装了（例如 `dia@dialectic-skills` 和 `dia@ajitta`，或一次上传加一次 marketplace）。删除其中一个。
- **claude.ai 上的 Skills 部分缺失或显示为灰色。** 打开 Settings › Capabilities › Code execution and file creation。
- **`dia-ratchet`、`dia-adjudicate` 或 `dia-techne` 无法启动。** 只有当技能名称是消息的第一个词，或被显式选择时（`/dia:dia-ratchet`、`$dia:dia-ratchet`、`@dia-ratchet`、`dia ratchet`；`dia-adjudicate` 和 `dia-techne` 用同样的形式和 `dia adjudicate` 或 `dia techne`），它们才会启动。仅凭 `dia <request>` 从不会选中它们，而是回复应发送的形式。
- **在 Codex 上 `$dia:dia-skopos:` 无法解析。** 技能名称后面应加空格，而不是冒号。
- **在 claude.ai 上上传被拒绝。** 请使用 Customize › Plugins › Upload plugin，而不是 Customize › Skills。
- **在 claude.ai 上 Check for updates 后仍是旧版本。** 在 Customize › Plugins 中移除 `dia`，再从 `dialectic-skills` 市场重新安装；如需自动获取后续版本，请打开 Sync automatically。

哪些途径已经验证过、如何验证的，记录在 [docs/probes.md](docs/probes.md) 中。
