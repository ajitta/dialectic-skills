# 적대적·독립 검증 결과: 반증가능성 문제는 기존 dia 스킬로 해결되는가

검증 대상(T): `dia-falsification-skill-need.md`
작성일: 2026-11-10

## 검증 구성

| 단계 | 에이전트 | 독립성 |
|---|---|---|
| 블라인드 판정자 | Opus | T를 보지 않고 플러그인 원문만 읽은 뒤, 같은 질문(P1–P5)과 라우팅 입력 6개에 답함 |
| 적대적 반박자 | Fable (다른 모델) | T를 받아 결론, 인용, 철학적 주장, 라우팅표를 공격함. 실패한 공격도 보고하게 함 |

- 웹 조회는 IEP와 SEP의 포퍼 항목뿐이며, 일반적인 공개 용어로만 검색했습니다.
- 두 판정이 갈린 항목은 제가 플러그인 원문과 대조해 정리했습니다(§3).

## 1. 결론

**질문:** 이 세션에서 논의한 반증가능성의 문제를, 현재 dia 스킬만으로 해결할 수 있는가?

**답:** 대부분은 기존 스킬로 해결됩니다. 해결되지 않고 남는 부분이 있는 것은 확실합니다. 하지만 그 부분을 메우는 데 새 스킬이 필요한지는 **아직 정당화되지 않았습니다.** 두 판정 모두 같은 결론에 이르렀습니다.

| 문제 | 판정 (두 판정 일치) |
|---|---|
| (가-1) 사전 기준·엄격성 기록 | **기존 스킬로 대부분 해결.** 유지 결과를 내는 스킬은 모두 시도한 것을 기록합니다(reductio, negative, warrant, quaestio, elenchus). 실제로 빈 곳은 `quaestio`가 falsification pull의 답을 기록하지 않는다는 점 하나입니다. 수정 비용은 T가 말한 것보다 큽니다(`regula` step 1의 의미 변경 절차) |
| (가-2) 비보편 경험적 주장의 반증가능성 감사 | **남는 부분이 있음. 다만 T가 말한 것보다 좁음.** 새 스킬은 조건부 후보로만 유지되며, 그 조건(사용 빈도, 기준선 비교)은 아직 확인되지 않았습니다 |
| (나) 스킬 준수 검증·효과 검증 | **플러그인 밖에서 다룸.** 블라인드 판정자, 반박자, 두 판정이 모두 동의했습니다. 반박자가 "(나)에는 스킬이 필요하다"를 공격했지만 실패했습니다 |

**해결되지 않고 남는 부분** (원문 대조로 확인됨)
1. "반증 가능한가?"라는 요청을 받는 스킬이 없습니다. router에서는 `None fits` 경로로 가서, 스킬 없이 일반 답변이 나옵니다.
2. `conjecture` Step 0의 안내 목록에는 **존재 주장**이 갈 곳이 없습니다.
3. 확률적 주장의 **결정 규칙**, 시험할 때 **고정할 보조가설**, 보유자가 **모든 반증 기준을 거부하는 경우**를 기록할 라벨이나 필드가 어느 스킬에도 없습니다.
4. 기한 없는 주장("결국 교정된다")이 `conjecture`로 가면, hard rule 2("a case whose check you cannot write is not raised") 때문에 반례를 하나도 제기하지 못합니다. 결과는 "stopped before testing"이 되는데, 이 라벨은 "형식상 반증 불가"라는 실제 발견을 가립니다. 이것은 추론이며, 실행해서 확인하지는 않았습니다.

**결정적 쟁점:** 위 공백을 새 스킬로 메울지, 아니면 가벼운 수정으로 메울지는 두 가지 자료로만 정할 수 있습니다. 하나는 사용 빈도이고, 다른 하나는 라우팅 입력 3–5(약 효과, 시장 교정, 숨은 패턴)에서 **스킬을 쓴 답과 일반 답변(None fits)을 비교한 결과**입니다. 가벼운 수정이란 `conjecture` Step 0에 행선지와 라벨을 추가하고, `quaestio` stress를 진입점으로 안내하는 것입니다.

반박자는 "가벼운 대안을 주 권고로 삼아야 한다"고 했고, 블라인드 판정자는 "새 스킬이 필요하다"고 했습니다. 두 판정은 둘 다 **증거보다 한 걸음 더 나간 주장**으로 보았습니다.

블라인드 판정자는 최강 반론으로 다음 순서를 제시했습니다. 반박자와 두 판정도 같은 방향을 가리켰습니다.
1. 평가 먼저
2. 그다음 `conjecture` Step 0 수정
3. 평가에서 일반 답변이 실패할 때만 새 스킬

## 2. T에서 확인된 오류 (두 판정 일치, 원문 대조)

| T의 주장 | 판정 | 근거 |
|---|---|---|
| 엄격성 기록은 `conjecture` Tried뿐 | **틀림** (중대) | reductio "list the directions and premise sets you tried", negative "list them", warrant "list the questions", quaestio "Say which tests did not happen" |
| `quaestio`는 선택지와 계획으로 끝나므로 결과물이 다르다 | 부분 성립 | stress 모드는 선택지를 건너뛸 수 있음("skip this step"). 다만 브리프에 반증 기준 필드는 없음 |
| 시장 예시는 방법적 면역화의 예이고, 그래서 대화형이 필요하다 | **예시로서 틀림** (중대) | 기한 없는 "결국"은 형식상 반증 불가이고, 기한을 붙이면 주장 자체가 바뀜. T 안에서도 "묻지 않고 판정"과 "기한을 묻는다"가 충돌함 |
| 보조가설을 한정 없이 면역화 장치로 열거 | 부분 성립 | 새로운 시험 가능한 예측을 낳는 보조가설은 정당함. 문제는 ad hoc한 보조가설뿐 (IEP, 요약 경유) |
| 비보편 주장의 면역화를 잡는 곳은 비어 있다 | 부분 성립 | `quaestio` "A belief nothing could disconfirm is a finding"을 빠뜨림. 다만 기록 필드나 라벨은 없음 |
| `regula` Rule 4 인용 | 부분 성립 | 생략된 부분에 범위 한정어가 있음("across the files a model reads together"). 따로 로드되는 스킬에 적용한 것은 유추 |
| 용어 분쟁을 `elenchus`로 "넘김"이 `conjecture` Step 4와 같음 | 부분 성립 | 원문은 넘기는 것이 아니라 제안하는 것이고, 해당 사례는 disputed로 남음 |
| 비용 목록 | 불완전 | router "A number from 1 to 13"과 각 스킬의 경계 목록이 빠짐 |
| 실패 관찰 상당수는 기계적으로 판정 가능 | 과장 | quaestio: "two asks joined into one sentence still count as two, even under one question mark". 라벨은 사용자 언어로 번역됨 |
| `emend`·`ratchet`은 준수를 판정하지 않는다 | 부분 성립 | `emend`는 기준 문서를 supplied material로 받아 판정할 수 있음. 이 점은 오히려 (나)의 결론을 강화함 |
| 권고 순서 (수정 → 평가) | 부분 성립 | 수정을 반증하려면 평가가 있어야 한다는 T 자신의 논리와 긴장이 있음 |

두 판정 모두 T의 핵심 인용 대부분(약 15건)이 원문과 일치한다고 확인했습니다.

## 3. 두 판정이 갈린 항목과 제 대조

| 항목 | 1차 | 2차 | 대조 결과 |
|---|---|---|---|
| 블라인드 보고서의 "형식 규칙은 린터로 기계 검사 가능" | 타당 | 과장 | **2차 채택.** quaestio hard rule 1 원문(세션 초반에 직접 읽음)이 의미 판단을 요구함 |
| 블라인드 보고서의 "자기 부여 심각도 등급을 플러그인이 피함" | 타당 | 부분 타당(조건 불일치) | **2차 채택.** warrant의 해당 규칙은 "When another agent fixes the output format" 절에 있고, 발견의 심각도에 관한 것이지 시험의 엄격성에 관한 것이 아님(원문 확인) |
| 반박자의 "평가 체계 단서가 플러그인 안에 있다"는 지적 | 과장 | 타당 | **둘 다 부분적으로 맞음.** 시험이 있었다는 단서(adjudicate lineage의 "trials", regula evidence.md)는 실제로 있음. 그러나 그것이 준수 검사 하네스가 있다는 증거는 아니며, T의 "확인하지 않음"은 사실 그대로의 서술임 |
| "숨은 패턴" 분류 | 반박자 쪽이 맞음(한정 존재) | 한정 존재인지 확정 불가 | **결론은 같음.** 막는 것은 "패턴"의 정의이므로 정의를 물으면 시험 가능해짐. "묻지 않고 반증 불가 라벨"이라는 T의 설계는 틀림 |

## 4. 다음 단계: 이 결론을 반증할 시험

새 스킬이 필요한지는 아래 시험으로 반증 가능하게 만들 수 있습니다. 기준은 시험 전에 정합니다.

- **입력:** 라우팅 입력 3–5와, 같은 유형의 변형 몇 개
- **비교군:** (A) 스킬 없는 일반 답변, (B) 가벼운 수정을 적용한 경로(`conjecture` Step 0에 행선지·라벨 추가, `quaestio` stress)
- **판정 기준:** 다음 네 가지를 미리 정한 기준에 따라 채점합니다.
  1. 형식상 반증 불가를 올바르게 명명했는가
  2. 확률적 주장에 결정 규칙을 요구했는가
  3. 고정할 보조가설을 기록했는가
  4. 기한을 붙인 판본을 주장 변경으로 기록했는가
- **채점:** 작성자와 다른 모델이 채점합니다.
- **반증 조건:** (A)나 (B)가 기준을 충족하면, 새 스킬의 필요성은 기각됩니다.
