# D43 proposals resolved in plugin 1.8.0: changes, reviews and A/B (2026-10-28)

Spec D47. The owner asked for every open meaning-change proposal of the D43 rewrite (`rewrite-2026-10-28.md`, table) to be resolved in one release, each toward the reading the file already supports, with an A/B where an existing eval reaches the change (dia-instruct step 1) and routing probes for dia-menu. dia-intent's row went into dia-intent 1.6.0 (spec D46, `ab-dia-intent.md` round 3).

## Method

- One sub-agent per skill (two small skills per agent) wrote the change from the released text, under one brief: resolve toward what a model following the file already does, add no behavior and no new reasons, keep the frontmatter, list what cannot be resolved without a new behavior as "needs owner", and flag every change an existing eval reaches.
- A sub-agent that did not write it reviewed each changed skill against dia-instruct (old and new text only). Confirmed findings were fixed; the fixes that changed meaning (dia-reductio, dia-menu, dia-negative, dia-elenchus) were reviewed a second time. All reviews were PASS or PASS WITH FIXES.
- A/B on the skill-effect eval tasks that reach a change (`docs/skill-effect.md`), ported to the Windows host: arm A is plugin 1.7.0, arm B the same with the changed skill files; Claude Code 2.1.312, claude-sonnet-5-5 and claude-haiku-5-5, default tools, fresh configuration and empty directory per run; dialogue tasks with the eval2 simulated respondent (sonnet, no plugin). Blind opus judge on the eval's checklist, plus one item for dia-reductio (sets out to refute, not to prove or argue both) and one for dia-ratchet (every quoted span of the draft is a clause or shorter). n=12 per arm and model; only runs whose first Skill call loaded the skill are counted (Haiku ratchet-draft loaded it in 6 of 12 runs per arm; every other cell 11 or 12).
- dia-menu: probes Part U (`docs/probes.md`).

## What 1.8.0 ships

- **dia-brainstorm 1.3.1:** the question-itself probe at `standard` or `deep` depth; the brief is not optional (Hard rule 6 now names the brief and the file Step 5 may save it in); the message with Step 5's brief is exempt from the phone-screen limit; Step 3 asks once about each edge, one edge per message; a repeated "what would you do?", in any words, counts as the wish to jump to Step 3; the question bank's tactic names match the skill's ("Falsification pull").
- **dia-elenchus 1.3.1:** a refutation built on a premise agreed only because of its wording is withdrawn, the premise asked again plainly and the conflict re-checked; Step 2 points to the patterns row for repeated examples; Step 3 reads the patterns file when first reached; Step 6 ends on a definition that survived several real tests, including those the holding bar requires, and names that bar.
- **dia-reductio 1.2.1:** Refute when the user asks to refute T or names no direction and does not ask whether T is true; Prove when asked to prove T; Both unchanged. Follow-ups: the options are give up or narrow a premise, give up T, accept T, or adopt T′; every follow-up adds a history line; Steps 3 to 8 rerun unless the option gave up or accepted T.
- **dia-negative 1.2.1:** the target bullets sit under Parameters (the `all` bullet keeps "run the procedure separately for each target"); "operative function" is the one name in the skill, its template and theory.md.
- **dia-counterplan 1.1.1:** a missing fact reads "not supplied" in its slot and goes under the record's "not tested"; a value the counterplan chooses is named in its slot, never as "not supplied"; the first message's early ends are listed (Step 1's question; the Step 8 record when Step 3 finds no key assumption on a counterplan request; after Step 3, with no record, on an assumptions-only request).
- **dia-warrant 1.1.2:** the one-line "starting in ask mode" note applies to all three ask triggers.
- **dia-conjecture 1.1.2:** a round ends after the user picks a repair for a counting case or after Step 4 settles any other ruling, and the next case follows then; the stop offer comes once, after the third round. The proposed "file tool" wording was reverted: the other skills say "filesystem".
- **dia-refine 1.2.1:** step 1 keeps a deliberate choice unless it conflicts with the user's instructions or a confirmed fact (was "a higher instruction"); a doubt on a quotation, a chosen name or the user's own figures is listed as step 3 lists unverified items, which also covers "final version only" mode. The proposed "closing line" wording in Safeguards was reverted, because default mode has no closing line.
- **dia-ratchet 1.4.1:** a blocked full text follows the content-filtering guardrail (one retry, then a change list); sources live in each judgment-log line's `method:` field; every quoted "original span" in the change list is cut to a clause or less.
- **dia-menu 1.2.1:** the gate (dia-intent, dia-ratchet, dia-adjudicate are never started from a plain request) is the first case under "Then:". The new rule-or-policy default ("dia-brainstorm otherwise") was reverted after probes Part U: a bare rule went to dia-counterplan or a question, not to dia-brainstorm.
