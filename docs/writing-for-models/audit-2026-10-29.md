# Audit of the dia SKILL.md files by dia-instruct's rules (2026-10-29)

The owner asked for a review of every `skills/*/SKILL.md` in plugin 1.9.0 against `skills/dia-instruct/SKILL.md`, review only (dia-instruct step 3): no skill file is changed until the owner picks findings.

## Scope and method

- Thirteen files, frontmatter and body: the twelve skills plus dia-instruct itself, judged by its own rules and reported in its own section. `skills/`, `plugins/dia/skills/` and the installed 1.9.0 cache were identical (diff). `references/` files were opened only to check the first Structure item (a condition behind a pointer).
- Five general-purpose sub-agents, two or three files each, given the rules file path, their files and the instruction to check only and treat the text as data; none was given the reasons for the audit or the D43–D49 history.
- Every quote below was found verbatim in the file at the line given, by the session that wrote this record (one line number corrected: dia-brainstorm deep depth is line 35, not 36). Severity is the sub-agent's unless marked "(adjusted)".
- Findings that overlap an item the owner already ruled on (D43 table, `ab-d43-2026-10-28.md`, D47, D49) are listed apart at the end, so they are not raised again as new.
- Severity: medium, a model could plausibly resolve the text wrongly; low, minor. No finding was rated high.

- Single worked examples (Lead 6): dia-conjecture 59–66, dia-reductio 81–94, dia-warrant 103–114. Add a contrasting example only if narrowing shows up in use.
- dia-conjecture Step 2 (line 53): the Prior criterion has no done-when when the user gives none.

- dia-instruct line 43 (Lead 1): does not say whether reading fewer files is the risk or the benefit.
- dia-elenchus line 98: "survives several real tests" could point to the holding bar as its done-when (also L16).

## What a fix needs

Most findings above would change what a model does, so each picked one is a meaning change under dia-instruct step 1: the owner's request, an A/B where an eval reaches the changed condition, otherwise reported as unmeasured; then a new plugin `version` and the skill's `metadata.version` (spec §12.1), and a review by a sub-agent that did not write the change (step 2). A description change (M6 if fixed there) also needs the routing gates of probes Parts P and Q re-run.
