# Rewrite of the dia skills by dia-instruct's rules (2026-10-28)

The owner asked, before the 1.6.0 merge, for every skill body to be rewritten by the rules in `skills/dia-instruct/SKILL.md`, so that a model reads and follows each file more reliably. Readability for people was not a goal. Spec D43 records the decision.

## Scope and method

- Eleven skills: dia-intent, dia-brainstorm, dia-elenchus, dia-reductio, dia-negative, dia-warrant, dia-conjecture, dia-counterplan, dia-refine, dia-ratchet, dia-menu. dia-adjudicate was already rewritten (D41) and dia-instruct is the rules file.
- Body only. Frontmatter, descriptions, `agents/openai.yaml` and `references/` are unchanged, so the routing gates of probes Parts P and Q still describe the same descriptions.
- Wording and structure only (dia-instruct step 1): conditions, limits and fallbacks moved into the sentence they gate, reasons attached where the file or its references already gave them, one name per thing, duplicates stated once. No behavior change was intended, so no A/B was run; the rewrite is unmeasured, which the owner accepted.
- One sub-agent rewrote each body; a second sub-agent that did not write it compared old and new against the rules file and for meaning (dia-instruct step 2). Every confirmed finding was fixed before the text was adopted: 9 PASS WITH FIXES, 2 PASS. The fixes restored the old scope where a merge had widened or narrowed a condition (for example dia-intent's ban on offering pre-approval investigation, dia-ratchet's span rule and lower-bound caveat, dia-refine's severity filter and the unmarked correction in "final version only" mode, dia-warrant's ask-mode offer, dia-conjecture's key-term dispute bullet) and removed reasons that were new content.
- Bodies changed by -2% to +3% in characters.

## Proposals not applied (meaning changes; for the owner)

Applied since (owner, 2026-10-28): the dia-warrant "Stop means stop" contradiction and the dia-conjecture global-only label, in plugin 1.6.1 (spec D44). The other proposals stay open (handoff item 31).

These came up during the rewrite. Each would change what a model does, so each needs the owner's request and, where an eval exercises it, an A/B.
